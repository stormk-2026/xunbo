## 实现与数据边界

- Application 唯一 AppContainer、唯一 SerialKeyExecutor；码表更新不创建新队列。停止取消等待驱动的任务，已进入阻塞写入的单帧可能收尾；没有重试或补发。
- 两种格式均校验字节范围；RAW4_INV 保持初始值，界面标明“寻播尚待真机验证”。格式设置写入 Room。
- USB 使用所选驱动的第一个串口，9600/8N1。授权只连接，不发键。学习先清接收缓存，累计恰好三字节；五秒预算包含缓存清理，不猜发学习命令。实际 USB 控制传输与超时误差需真机检查。
- Room v1 schema 在 app/schemas/；保存码表、格式、标定和记录，无破坏性迁移。旧库只读取固定 ir_keys 表与字段，不替换 App 数据库。默认保留已有，源内重复默认取第一条，明确覆盖取最后一条。批量失败有 Fake 测试，真实 SQLite/Room 异常回滚仍需设备验证。
- CameraX 旋转校正后的完整图像同时供预览与标定；FIT_CENTER 留黑边，触点反算到归一化图像坐标，首点冻结画面。Android Matrix 做四点透视矫正，像素留在适配层。尺寸/旋转失配不应用旧标定。
- 可见 Activity 发起前台会话，通知可停止；START_NOT_STICKY，不重放键。结束释放相机/USB，Activity 重建仍用同一容器。
- M1 无网络权限或云调用，运行不消耗 Jev/LLM token。帧仅按用户勾选采集，保存在 App 私有 files/frames，经系统文档选择器手动导出。
- 手动记录独立于 TraceStep，含会话、USB 信息、格式、按键、排队/发射调用耗时、发射与前后帧单调时钟时间、人工结果及错误。writeReturned 仅表示调用返回，不表示电视成功。
- 后帧 500ms 是取样延迟，不是稳定判定；writeMs 包含协程调度及写入调用开销。导出可按会话/单调时钟差值算实际间隔，不能跨手机重启比较。
- ZIP manifest.json 显式包含 schemaVersion、MANUAL_DEBUG、UNLABELED、缺失附件及未采到图像的记录。有效标定时截图为电视区域，否则为完整取景；calibration 为 null 不能称为已校正图像。

## 真机手动验收步骤

1. Android Studio 打开项目，JDK 用内置 JBR，选择已连接真机 Run app。连接自己的 IRTM，点“刷新 USB 设备”并选择连接；验证授权允许/拒绝及拔出状态。连接不得发键。
2. 保持 RAW4_INV，点“启动相机与调试会话”，授予相机权限，按需授予通知权限。后置相机对准电视，检查取景方向；拒绝授权后可恢复，不应循环请求。
3. 点“重新标定”，依次左上、右上、右下、左下，切“电视区域”检查。点错退出再标；尺寸/旋转变化后重标。检查前后台及 Activity 重建时的状态。
4. 选方向键，点“学习此键”，让模块收到遥控学习数据；核对三字节再保存。验证取消/超时不存半包。也可选择一致性导出的 ir_keys.db，核对数量后默认保留已有；重启 App 检查持久化。
5. 在安全且有移动余量的菜单逐次试发并立即标注实际效果，按需勾选截图。固定设备/格式/串口，连续计入 50 次方向键尝试，至少 49 次恰好移动 1 格；失败/取消/未判定不能删掉。未标注不算成功。
6. 空闲时切 A1F1 做安全单键对照。无响应记录不适配，不盲发；换配置另开完整一轮，不混算。OK/POWER 试发需额外确认；M1 无危险焦点自动识别。
7. 验证排队后停止、学习中停止、拔线、通知停止与重开，不得复发旧键。停止释放 USB，下次先重新连接再启动会话；前后台切换不得重复发送。
8. 点“手动导出全部记录与关联截图”，通过系统选择器保存 ZIP，核对清单/图像并填写下表。失败目标可能是不完整 ZIP，界面不报成功，重新导出到新文件。

- [USB host](https://developer.android.com/develop/connectivity/usb/host)：immutable PendingIntent，回调后以 hasPermission 核验所选设备。
