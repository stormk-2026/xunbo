# M0 — 骨架、契约、FakeTv mock 闭环

状态：已实现，待用户验收（2026-09-30）；见 `../verification/M0.md`。已同步开工前 RFC；一次只做 M0，完成检查后等用户验收。

## 摘要

- **目标**：从空目录建成可编译的 Gradle 多模块工程；按 `docs/contracts.md` 落地 `core:model`；用 FakeTv + RuleStubDecider 在 JVM 上走通“从当贝精品桌面进入教育 tab”；`app` 能 `assembleDebug`，界面只表明这是 M0。
- **非目标**：真机红外、CameraX、OCR、Jev 真 API、Room、语音、技能回放、完整 UI、OpenCV、任何云调用。
- **模块**：`:app` `:core:model` `:core:decision` `:core:navigation` `:core:agent` `:core:testing`
- **风险**：空仓库没有 wrapper；契约实现偏离文档；把 M1 硬件做进来。
- **验证**：`./gradlew ktlintCheck lint test assembleDebug`（若 ktlint 尚未接入，先接入再跑；不要跳过）。

## 先读

`AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/lessons-from-bobo.md`。本轮先同步已批准 RFC，后续契约修改仍需批准。

## 工程约束

- 包名 `com.stormg.xunbo`，namespace / applicationId 一致。
- Kotlin 2.2.20 + AGP 8.13.1 + Gradle 8.14，compileSdk/targetSdk 36（采用本机兼容的稳定组合，不追逐最新大版本），写进 `gradle/libs.versions.toml`。minSdk 26，targetSdk 36。
- 含 `gradlew`。Java/Kotlin 字节码目标 17；Gradle 可使用 Android Studio 内置 JDK 21（本机未独立安装 JDK 17）。
- 手写 `AppContainer`，无 Hilt/Koin。
- JVM 模块：`java-library` + Kotlin，单元测试用 JUnit 4 或 5，选一个并全仓库统一。
- 代码风格：官方 kotlin style。接入 ktlint（`org.jlleitschuh.gradle.ktlint` 或等价），规则保持默认，不要放宽。
- `.gitignore` 排除 `build/`、`.gradle/`、`local.properties`、`.idea/`、`*.iml`、`traces/`。
- 根目录放简短 `README.md`：项目一句话、怎么跑 `./gradlew test`、文档入口 `docs/README.md`。不要写空话产品文案。

`local.properties` 不要提交。sdk.dir 由本机 Android Studio 生成。

## 要实现的代码

严格按 `docs/contracts.md` 的名字实现。缺类型就停下来写问题，不要私自改名。

### `core:model`

- 全部 data / enum / 端口接口
- `TextMatch.normalize` / `matches`
- `DefaultDangerGuard`（实现 `DangerGuard`）
- `IrKeyNameParser`（旧中文名 → `RemoteKey`）
- `goalKey` 生成函数 `GoalKeys.of(intent: TaskIntent): String`
- `PerceptionThresholds` / `DecisionThresholds` 默认值

### `core:decision`

- `JevStateBuilder.build(task, screen, recentSteps): String`  
  必须包含契约第 5 节列出的四块；elements 最多 30。
- `DecisionPolicy`：输入 `DecisionResult + ScreenState + Task`，输出本地指令  
  `Proceed` / `PressBack` / `PressHome` / `Stop` / `CheckPostcondition`  
  规则按契约护栏实现。
- `RuleStubDecider`：不联网。用规则：仅服务 M0 栏目场景：activeTab 已到目标时 arrived=1 候选；否则可信焦点已在目标时 ok_current；否则选择目标 tab element。用于 demo，不是真 Jev。

### `core:navigation`

- `GridFocusNavigator`：在已知 `elements` 的 row/col 或中心点上选方向，一次最多发一个 RemoteKey，返回 NavStepResult；重试归控制器。
- 通过 `KeyExecutor` 发键，再 `ScreenObserver.waitUntilStable()`，比较焦点，返回 `NavStepResult`。
- `pressOkIfSafe` 接 `DangerGuard` 和 `TextMatch`。
- 循环列表：若移动后焦点位置和已观察路径证明绕回（不得仅凭同名文字），outcome=`WRAPPED`。

### `core:agent`

- `RuleIntentParser`：能解析  
  - `在教育分类下找小猪佩奇第23集` → hintTab=教育, title=小猪佩奇, episode=23, action=PLAY  
  - `进入教育` → hintTab=教育, action=OPEN, postcondition=`ActiveTab("教育")`，只有执行 OK 激活后才成功
- `DefaultPostconditionChecker`
- `ExploreController` + `TaskRunner`：感知 → stub 决策 → policy → navigator。无 Skill 回放。
- `InMemorySkillStore`（M0 可空实现：find 恒 null，save 记在内存供测试断言）
- `InMemoryTraceSink`；FakeClock 在 testing

### `core:testing`

- `FakeTv` + 场景 `DangbeiHome`：顶栏 10 个 tab，默认 active=`精品`，焦点先在内容卡片「沙漠往事」。从内容区按 UP 进入 tab 栏（落在「精品」），再左右到「教育」，OK 后 `activeTab=教育`，焦点 text=`教育`。
- FakeTv 实现 IrTransmitter / Perception / FrameSource；FakeScreenObserver 组合感知；navigation 中串行 KeyExecutor 驱动 FakeTv。
- 方向键改变焦点；OK 只在焦点为某个 tab 时切换 `activeTab`。

### `:app`

- 单 Activity + Compose：标题「寻播 M0」，正文说明硬件未接、请跑单元测试。
- `AppContainer` 保留空壳容器入口，不引用 testing；完整 Fake 闭环在 JVM 集成测试组装。
- 权限先不要申请相机/USB（M1 再加）。`AndroidManifest` 不要多加任务单没写的权限。

## 必须先写再实现的测试

在 `core:testing` 或各模块 `src/test`：

1. `TextMatchTest`：相等、包含、过短单字不匹配、`第23集` vs `23`（仅 episode 场景）。
2. `DangerGuardTest`：重启、恢复出厂、购买、`9.9元`、`¥12` 为危险；「教育」「小猪佩奇」不危险。
3. `IrKeyNameParserTest`：确定→OK，返回→BACK，设置→MENU，UP→UP。
4. `JevStateBuilderTest`：输出含 hintTab、focus、不超过 30 个 element id。
5. `DecisionPolicyTest`：popup 高 → Back；confidence 低 → Stop 或 Back；arrived 高 → CheckPostcondition。
6. `PostconditionCheckerTest`：`Selected("1080P_50Hz", on=true)` 在只有 focus 而 selected 为空时失败（防止重蹈 bobo 谎报）。
7. **端到端** `ExploreEducationTabTest`：  
   任务 raw=`进入教育`，FakeTv 初始在精品内容卡片。  
   20 步内 `TaskStatus.SUCCEEDED`，最终 `activeTab` 匹配教育。  
   trace 里每一键都是单键，不存在“一次 send 多个 key”。  
   不得出现 `RemoteKey.POWER`。

没有这些测试不要写实现。Fake 跑通只证明 M0，报告里不要写“真机可用”。
