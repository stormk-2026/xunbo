## 摘要

目标：在用户自己的手机和 IRTM 上提供可验证的手动调试链，包括单键发射、学习与导入、相机取景、四角标定、前台服务、停止及手动导出记录。

非目标：OCR／焦点自动识别、Jev、自动任务、技能回放、语音、多设备适配、发布或商用部署。M1 的方向键效果由用户观察标注，不能拿 USB 写入成功代替电视确实移动。

涉及模块：app 中的 Android 适配、Compose、ViewModel、Room；core:agent 的调试用例；core:navigation 的执行队列；core:model 经批准新增的端口；core:testing 的 Fake 与回归。保持六模块结构。

主要风险：串口碎片／超时／断开、停止与入队竞争、重复按键、相机旋转与预览坐标不一致、覆盖已有按键库、把手动测试误报成自动识别成功。

验证：先写失败单测，离线运行四项交付检查，然后由用户用 Android Studio 在已连接真机上运行验收。禁止模拟器。

## 1. 红外连接与按键管理

- usb-serial-for-android；9600、8 数据位、无校验、1 停止位。
- 用户选择并连接 USB 设备，处理系统授权、拒绝、拔插、串口占用和异常；不能连接后自行发键。
- RAW4_INV 编码为 `[u1,u2,cmd,(~cmd)&0xFF]`；A1F1 编码为 `[0xA1,0xF1,u1,u2,cmd]`。字节字段必须在 0..255。
- 暂沿用旧设备已验证的 RAW4_INV 作为试验初始值，界面标注“寻播尚待真机验证”；可以手动切换并持久化。不得未经真机证据擅自更换默认。
- 一个 AppContainer、一个设备会话、一个全局 KeyExecutor；所有发射都经过串行执行器。
- 每次点击只提交一键，没有自动连按／长按连发。显示待发数和当前发送状态；用户点停止立即作废待发操作，已进入传输的单帧允许收尾。恢复发送需要新的用户操作。
- 学习模式最多 5 秒，累计串口分片直到获得 3 字节；取消、超时、拔线均不能保存半包。学习与发射互斥，拒绝同时试发，不猜额外学习命令。
- 学习结果先预览再保存；已有键覆盖、删除均需用户明确操作。未学习的键不可试发。POWER 等只在手动调试区由用户点名操作。

## 2. 本地存储与旧库导入

- Room + KSP 保存按键、帧格式、标定信息和手动调试记录；依赖统一放版本目录，不升级现有工具链大版本。
- 通过系统文件选择器选择用户手动导出的 ir_keys.db；按旧表 name/userCode1/userCode2/commandCode 读取为输入数据，不执行库中任意 SQL，不替换寻播数据库。
- 导入先展示可导入、未知名称、非法数据和同名冲突数量；默认保留现有键，只在用户明确选择后覆盖冲突项。失败事务不影响原库。
- 旧库若仍有未合并的 WAL，提示用户提供一致性导出；不能声称单个数据库文件必定包含全部最新按键。
- 不自动连接旧 App，不删除或重置用户数据；不使用 destructive migration。
- Skill 的 Room 存储可按既有 SkillStore 接口实现；不提供回放或自动学习功能。

## 3. 相机与标定

- 用户启动调试会话后使用后置 CameraX，横置手机支架，显示预览。
- 用户依次点选左上、右上、右下、左下；坐标保存为旋转校正后的完整图像归一化坐标。预览裁切／缩放必须可逆映射，不能直接用屏幕触点当图像坐标。
- 校验四点有限、范围合法、互异、凸四边形且非零面积；无效标定不保存。
- 在 Android 图像适配层做透视矫正并提供电视区域预览／截图，Bitmap 和 ImageProxy 不进入 ViewModel、core 或 agent。
- 相机分辨率／旋转改变时检查标定是否仍适用，失配要求重标定；旧记录保留，不默默使用错误坐标。
- 帧仅保存在 App 私有目录；FrameSource 提供帧身份，不引入 OCR 或伪造高置信度 ScreenState。

## 4. 前台会话与界面

- 调试页：USB 连接状态、相机状态、队列状态、格式选择、取景与标定、按键学习／导入／试发／删除、明显的停止按钮、记录与导出。
- 用户从可见 Activity 启动前台调试会话，通知显示运行状态和停止入口；结束会话释放相机和串口。
- UI → ViewModel → core:agent 调试用例 → 端口 → Android 适配。UI 仅承载 Android 预览适配组件，不能在页面事件或 ViewModel 中直接读帧、写串口或处理 Bitmap。
- 服务／Activity 重建不得重放上次按键，不重复创建执行器。

允许的新增权限与能力（本任务单批准后才加入）：

- CAMERA（运行时请求）。
- FOREGROUND_SERVICE、FOREGROUND_SERVICE_CAMERA、FOREGROUND_SERVICE_CONNECTED_DEVICE。
- POST_NOTIFICATIONS（适用 Android 版本请求；拒绝时遵循系统前台服务行为并显示状态）。
- USB host feature 及系统 USB 设备授权，不把它当普通 manifest 危险权限。
- 不加入 INTERNET、录音、定位、宽泛存储权限；导入／导出使用系统文档选择器。

具体 Android 版本行为、PendingIntent 标志和依赖版本在编码前查官方文档，不能照抄旧 App 的历史实现。

## 5. 记录与手动导出

- 手动记录与自动 TraceStep 分开标明来源。记录会话、设备信息、帧格式、按键、队列／写入耗时、可用的前后帧、结果或错误码。
- 用户可标注“移动 1 格／无变化／跳格／方向错误／不可判定”；未标注不算成功。
- 每次采集与导出由用户触发；ZIP 通过系统文档选择器写到用户选择的位置。导出包含 schema 版本、记录、关联帧和标定；没有图像时如实注明，不构造空证据。
- 不记录 API key、Authorization 或请求头，不自动上传。M1 不调用云。
- 现有 TraceStep 不添加 Android 路径或 Uri；手动记录及附件关系放 Android 存储／导出模型。

## 6. 必须测试的行为

先失败后实现：两种帧编码及非法字节；学习分片、超时和取消；串行、停止、拔插时禁止后续键；新会话不得复发旧键；名称映射、重复导入、冲突与失败回滚策略；标定次序与几何校验、预览到图像坐标变换；导出清单和缺失附件处理。

用 Fake 串口、相机和存储测试 core 用例。Android 绑定行为有适当本地测试或设备手动验收，不能把纯 Fake 通过写成驱动／CameraX 已验证。保留全部 M0 回归。

```bash
./gradlew ktlintCheck lint test assembleDebug
```

## 7. 真机验收口径

1. 用户在 Android Studio 运行 App，完成 USB／相机授权，验证拒绝和拔插后的状态。
2. 学习或导入方向键，重启 App 后仍能读取；不丢失此前存储。
3. 四角标定后的电视区域方向正确、不包含大块桌面背景；改变取景条件后可重标定。
4. 在有足够移动空间的安全菜单，用户每次只试发一个方向键并标注效果。固定设备、协议格式和串口配置，连续计入 50 次样本，至少 49 次恰好移动 1 格（≥98%）。不得删除失败样本；若改配置，另起完整一轮。
5. 对另一帧格式做安全的单键对照并记录；若无响应则报告不适配，不为凑结果继续盲发。
6. 验证停止清队列、会话重开不复发、学习超时、USB 拔出和权限拒绝；后台／前台切换保留一致会话状态。
7. 用户手动导出 ZIP，验收记录填写实际路径、发送耗时、等待间隔、50 次分类计数与失败步骤；这些数值不得由模型代填。

M1 没有自动任务验收，焦点和选中态自动识别留到 M2。真机未验收之前状态只能写“待验收”。
