# 寻播工作链与开发 Harness

状态：**已确认，M0 已实现、待用户验收；后续阶段待逐阶段开放**。
日期：2026-09-30。

本文件根据本目录全部 12 份原有文档整理。“Harness”指约束开发和运行过程的任务单、接口、测试、执行护栏、轨迹与验收机制，不代表新增服务端或框架。用户本轮已授权整理规范；冻结契约的变更另见 [RFC](rfc/2026-09-30-m0-contract-clarifications.md)，用户于 2026-09-30 授权实施，现同步生效。

## 1. 要构建的工作链

运行工作链：

```text
用户文字／语音目标
  → Task（意图、后置条件、步数和时长上限）
  → 手机相机 → 电视区域标定 → 本地 OCR／焦点／选中态
  → ScreenState
  → 技能检索：已知路径回放，或 Jev 文本决策选择目标
  → 本地策略与危险项拦截
  → 几何导航 → 唯一 KeyExecutor → USB IRTM → 机顶盒
  → 重新观察、逐键验证
  → PostconditionChecker 判定
  → Trace／PageGraph／成功技能 → 下次复用
```

App 承载交互、相机和 USB 适配、生命周期与本地存储；纯 JVM 模块承载可独立测试的任务、决策、导航与验证逻辑。这里的“工作链”按已有文档理解为设备运行闭环及开发验收闭环；文档尚未定义 App 以外的业务系统或入口，不自行增加。

开发工作链：

```text
产品目标 → 冻结契约 → 当前任务单 → 失败测试 → 最小实现
  → 离线构建与回归 → 用户真机验收 → 验收记录 → 开放下一阶段
                           ↓ 不通过
                   失败 trace／fixture → 回归测试 → 修复
```

## 2. 阶段与交付物

以下沿用 architecture.md 的阶段，只有 M0 已有任务单。M1–M7 不因本表而开放实施。

| 阶段 | 构建环节 | 关键交付／验收证据 |
|---|---|---|
| 开工前 | 文档、契约与协作规则对齐 | 用户确认本提案和 RFC，随后同步原文档 |
| M0 | 工程骨架、JVM 契约、FakeTv、离线闭环、App 空壳 | 四项 Gradle 检查；20 步内真正进入教育；用户审阅工程和测试 |
| M1 | USB 红外、学习与导入、相机、标定、调试台、trace | 用户手动控制；50 次方向键至少 49 次正确移动一格 |
| M2 | 本地文字、焦点、选中态与页面识别 | 标注 fixtures；识别指标 ≥85%，单帧 <400ms；指标口径在任务单冻结 |
| M3 | Jev 文本接口、安全导航、设置任务后置条件 | 真机设置 1080P 50Hz，10 次至少成功 9 次 |
| M4 | 真实页面探索 | 教育下播放小猪佩奇，10 次至少成功 7 次，平均 <60s |
| M5 | 技能存储、逐键回放与失配恢复 | 同目标第二次 <15s；landmark 失配能停止回放并探索 |

架构中的性能数字目前是目标预算，不是测量结果。后续任务单必须指定设备、数据集版本、样本量、起止时刻、失败是否计入统计，以及平均值／分位数的口径。

## 3. 任务与批准规则

任务状态：待确认 → 已授权 → 实现中 → 待用户验收 → 已验收；阻塞单独记录原因。代码和检查通过只可称“待验收”。

- 文档审阅轮已结束；本轮实施 M0，不连接设备或 Jev。
- 用户批准本提案与 RFC 后，先同步 AGENTS.md、architecture.md、contracts.md、M0.md 和交接文档中的冲突，再实施 M0。不能只批准提案却让旧粘贴提示继续误导实现。
- 冻结契约由 contracts.md 定义；修改通过 RFC 批准并同步。任务单定义本阶段范围，若与契约冲突则报告，不能默选一份覆盖另一份。
- 文档默认由 Cursor 维护，代码由 Codex 实现；用户明确委托时 Codex 可维护文档。不得同时编辑同一目录。验收客观证据可由 Codex 起草，用户结论留给用户。
- M0 验收环境为 Android Studio 工程、构建与 JVM 测试；M1 起按任务单真机验收。全阶段禁止模拟器。
- 后续每阶段先补任务单，再获得用户授权；不得将路线图当作所有阶段的实施授权。

## 4. 开工前发现的冲突与建议

| 问题 | 影响 | 建议 |
|---|---|---|
| FocusOn／TextVisible 被允许代表“进入教育” | 初始画面已有教育文字，焦点到达也未必执行 OK | 新增明确的 ActiveTab 后置条件，见 RFC |
| matches 两参数接口无法接收集数场景，包含匹配又直接接受数字子串 | 23 与 123 可能误匹配，无法落实“仅 episode 场景” | 明确独立集数匹配规则，见 RFC |
| moveTo 被描述成完整导航和单步导航两种含义 | 内部重试可能绕过步数、停止与逐键 trace | 单次调用最多发一个键，重试归控制器，见 RFC |
| 页面 fingerprint 不含焦点，却被用于判断画面稳定 | 焦点移动时 fingerprint 可不变 | 页面身份与视觉稳定分别判定，见 RFC |
| AppContainer 要组装 Fake，testing 却只允许 test 使用 | App 无合法方式引用共享 Fake | M0 App 仅空壳与容器入口，Fake 在 JVM 集成测试组装；同步任务单 |
| FakeClock、RuleStubDecider 的模块归属有多处说法 | 重复实现或依赖倒置 | FakeClock／FakeTv 归 testing，RuleStubDecider 归 decision；端口归 model |
| FakeTv 在契约实现 IrTransmitter，在任务单直接实现 KeyExecutor | 测试可能绕过真正队列 | FakeTv 模拟设备及感知；共享串行 KeyExecutor 通过 Fake IrTransmitter 驱动，见 RFC |
| Stub 的“目标 tab 尚未激活”优先于“焦点已经到达” | 反复选择同一元素、不执行 OK | 优先判定已激活，再判焦点到达发 OK，否则移动 |
| Stub 声称判断任意后置条件，但输入文本未包含后置条件 | 决策与完成检查职责混淆 | M0 Stub 仅处理教育场景候选；成功仅由 checker 判断 |
| 连续无变化后 Stuck 与固定策略里的 BACK／HOME 冲突 | 卡住后继续按键 | 同键重试一次仍无变化即终止 STUCK，同步固定策略 |
| 循环只按文字判断 | 重名元素、未移动可能误判循环 | 结合位置与已观察路径；无法证明时停止，不猜反向 |
| 任务时限缺少挂起调用的超时规定 | WAIT／观察阻塞可能永不返回 | 单调时钟、共享截止时间、停止与超时取消测试，见 RFC |
| “原有失败”和工程尚未建立未区分 | 会把未运行写成测试失败或通过 | 基线显式记录不可运行及原因 |
| 旧资料提到根目录截图，但目录中不存在 | 无法核验 FakeTv 的视觉来源 | M0 以文字场景为准；M1/M2 另收真机材料，不伪称已有 fixture |

## 5. 每阶段任务单必须写清

1. 状态、目标、非目标、前置验收、允许修改的模块和文件。
2. 输入／输出、冻结契约引用、依赖和新增权限；涉及契约变更的已批准 RFC。
3. 正常路径、失败路径、停止和超时行为、测试与真机指标口径。
4. 构建命令、手动验收步骤、证据位置、已知限制。
5. 六层报告与用户结论；下阶段开放条件。

M0 在原有七组测试外需补：停止后不再发键、观察／决策挂起超时、重试计数、低置信度不按 OK、不误报 tab 成功、危险文字与价格、序列化往返。测试落在各模块本地单测及 testing 的集成测试，避免生产模块反向依赖 testing。

## 7. 自主寻找与商用边界

用户仅提供节目、栏目或类目目标；状态 JSON 和下一步动作均由系统自动生成。后续允许 Jev 依据每次视觉反馈选一个动作，M0 仍按冻结目标导航端口做离线验证。M3 先完成 100 次代表性决策的延迟、正确率与 token 实测，再评估真机端到端可用性。当前是单设备实验；商业发布不是本轮交付范围。
